# Gotchas and Fragile Boundaries

## Installable and contributor-context boundaries

- `skill/snowe-ui-skill/` is the copied product. Repository atlas/task state, evaluations, benchmarks, tests, browser script, and maintenance scripts remain outside it.
- `agents/openai.yaml` and copied `LICENSE` are intentional product files.
- Root `AGENTS.md`, `docs/atlas/`, `scripts/atlas/`, and `.agents/skills/atlas-maintainer/` are durable public contributor infrastructure. Their AI-assisted use does not make them private or installable product content.
- `.codex/`, non-allowlisted `.agents/` content, work/output/log directories, raw memory/handoff files, and personal runtime configuration remain ignored. Never solve a missing-public-context defect by publishing those artifacts.
- Reference figures ship in every install. Their HTML sources stay in `docs/figures-src/`; re-render with `render.mjs` (120 KB per figure) on Windows, because other systems substitute the system fonts the committed PNGs use. A caption that no longer matches its image teaches the image, not the caption.
- The structural generator reads tracked files plus nonignored candidate additions. If a durable path is accidentally ignored it disappears from `repo-map.md`; if private state becomes visible it can contaminate the map. Run both context and atlas checks after ignore-rule changes.

## Imports and console behavior

- Product scripts use bare sibling imports; this is not an installed Python package. The entry scripts (`search.py`, `corrections.py`, `visual_review.py`, `icon_review.py`, `glyph.py`) add their own directory to `sys.path`, so they also run under `python -I` / `PYTHONSAFEPATH`; run as programs they set `sys.dont_write_bytecode`, so an installed (possibly shared or read-only) skill never gains a `__pycache__`; `iso.py` imports no sibling module. Library modules imported directly (as tests do) still need the scripts directory on `sys.path`.
- UTF-8 console normalization exists in `search.py`; direct module callers do not inherit it.
- `checked_evidence.read_json` accepts UTF-8 with or without a BOM and rejects UTF-16/32 (Windows PowerShell 5.1's default for `>` and `Out-File`) with a message naming the file. Keep `object_fields(..., name=...)` labels on new call sites so field errors name the object.
- JSON mode reserves stdout for one valid JSON document; persistence summaries go to stderr. Packet-only and search-only flags are rejected outside their owning mode rather than silently ignored.

## Deterministic framing has deliberately low authority

- The packet is language-neutral because it does not interpret the brief, not because it contains a multilingual classifier.
- Do not restore `_SIGNAL_RULES`, query expansions, pressure mappings, language-specific synonym tables, automatic work-mode/platform inference, or fallback domain detection.
- Ambiguous terms and unknown domains must remain unresolved unless a caller supplies verified context. `UNKNOWN` is preferable to plausible false confidence.
- Caller-declared pressures are free-form and passed through. Do not limit them to a catalog.

## Retrieval is evidence, not design

- General search requires an explicit domain. BM25 remains lexical and may be English-oriented, but this affects only caller-requested lookup, never packet framing.
- `core.tokenize` applies the same stopwords, light English stemming, and hyphen joining to query and rows. Keep it normalization: do not grow it into a synonym table or query expansion, and remember that a row field added to `search_cols` changes ranking for every query in that domain. Missing vocabulary belongs in the catalog (with a manifest note), not in code.
- Product analogs are off by default. `--analog-query` is caller chosen, limited, labelled `UNVERIFIED_ANALOG`, and its absence changes no situation/architecture field.
- Every domain and stack result retains `source_role` and `warning`. Stack responses also count returned rows with and without `Docs URL`; a present URL is not automatically current/primary, and a missing URL is explicitly unsourced bundled guidance. Removing these boundaries can turn a snapshot into apparent authority.
- Landing/layout, style bundle, palette, typography pairing, and motion preset catalogs were deleted. Do not reintroduce their solution fields under a new evidence label without provenance and an observed failure that outweighs anchoring.
- `icon-candidates` requires exactly one supported family and a real subject; compare sources through separate auditable lookups.
- `AVAILABLE_STACKS` iterates only live stacks, but its membership test also admits `RETIRED_STACKS` names so `search.py`'s argparse `choices` lets `--stack uwp` reach `search_stack`, which returns an explicit retirement error naming `winui`. Code that needs live stacks only should test `STACK_CONFIG`.
- `CSV_CONFIG`/`STACK_CONFIG` headers are exact contracts; malformed quoting or renamed columns can silently empty fields. `tests/test_catalogs.py` requires every bundled CSV to be BOM-free UTF-8 with LF endings, a final newline, a rectangular shape, unique `No` ids, and every configured column present.
- Changing a bundled CSV's row count, or adding or removing one, requires updating `data/CATALOGS.md`; the manifest test compares every listed count with the file. Keep the upstream MIT notice there while any derived catalog ships.
- `web` is a compatibility alias of `mobile` (the same `CSV_CONFIG` object). Do not give `web` browser-guidance wording: every `app-interface.csv` row is iOS/Android/React Native.
- Filtering a column out of output does not remove it from the installed file. `tests/test_catalogs.py` scans every cell of every bundled CSV for hex colors, millisecond durations, Tailwind color utilities, numbered template prescriptions (`dashboard-01`), and frame-rate claims. Its `PENDING_OUTSIDE_THIS_CLEANUP` exception set is empty: every catalog is clean. Code examples use placeholders such as `#RRGGBB` or semantic tokens instead of concrete palette values. Quotes inside fields use CSV doubling; a backslash-escaped quote is rejected because it silently truncates code examples.

## Open-decision and progressive-disclosure contracts

- `--design-system` aliases `--decision-packet`; it must not resurrect recipe generation or old numeric dials.
- Calibrate from the observed consequence and actual owner/consumer change surface, not English keywords, request category, or file count. Search exact user-supplied product/feature/route/visible-label identifiers in paths **and content**, then follow manifests/entrypoints/rendered routes before declaring a target absent.
- The deterministic scope fixtures use an authored boolean uncertainty-surface record only to test route consistency. Do not turn those fields into a runtime classifier or infer them from task text. Exact per-case reference/process/artifact/stop/escalation contracts, exact progressive-route reasons, and the structurally closed Direct/Focused/Portfolio Delivery obligations prevent contradictory global workshop claims from passing.
- Architecture, imagery, custom work, and motion remain open, with no image/custom asset/animation valid.
- A Direct correction records and proves only the affected invariant; it skips packets, broad research, candidate generation, architecture, unrelated assets/motion, and full designer evaluation. A shared owner or one unresolved established-system choice is Focused. Portfolio activates only for named material goal/topology/journey/content/interaction/responsive/system-contract uncertainty. High consequence increases failure-mode proof without automatically increasing process breadth.
- Architecture work should not load iconography without a live icon decision. A no-image result ends generation work. A routine learned glyph in an accepted family does not trigger custom drawing.
- Automated `KEEP` proves epistemic boundaries only. It cannot certify architecture, aesthetic distinction, icon optics, motion quality, or responsive coherence.
- Worked examples in product references must not use the domains of the measured briefs in `evals/skill-outcome/briefs.json`, or the measurement can reward a pre-written answer. The art-direction derivations describe fonts by structure and role, not by family name, so they do not reintroduce a typography-pairing recipe.

## Persistence and paths

- Re-running persistence atomically replaces `BRIEF.md` and a matching requested page inquiry but preserves `DECISIONS.md` via exclusive creation.
- Project/page names are identities as well as path inputs. `PROJECT.json` and embedded page identity prevent distinct printable values from silently sharing a normalized slug; nonprintable or Windows-reserved identities, redirects at or below the selected root, external hardlink targets, and competing slug claims are rejected before replaceable inquiry writes. Resolve only the caller-selected root (`_resolve_selected_root`: `--output-dir`, `--workspace`; `_resolve_selected_file` resolves the directory of an `--input` file), once, so macOS `/tmp` and `/var/folders` work; never resolve a path below it. Expand Windows 8.3 aliases on the resolved root, recheck both spellings to the drive root after expansion, and keep containment lexical beneath the resolved root.
- Lexical redirect-chain checks that walk to the filesystem root (`asset_quality.py`, `icon_review.py`, `decision_packet._reject_reparse_chain`, `scripts/install_skill.py`) accept only the macOS OS-owned root aliases `/tmp`, `/var` and `/etc` that resolve into `/private`; the default macOS temporary directory lives below `/var`. Any other symlink, junction or reparse point, including one with the same name below the root or a root alias pointing elsewhere, stays refused (`tests/test_system_root_aliases.py`).
- A bounded torn-manifest recovery path must never infer identity from a slug alone. Keep the per-project lock, page preflight, and immediate parent revalidation: there is no database or multi-file transaction, so these serialize known races while preserving per-file atomicity.

## Validators

- Icon preview language is explicit in schema 1.1/1.2; 1.0 remains supported. Schema 1.2 additionally binds symbol role and exact brand identity; known brand assets need no custom challenger. Long/localized headers and no-icon text buttons need their own containment checks, not only document overflow. Inspector chrome remains English while target preview content carries its declared language/direction.
- Correction checks validate recorded proof, not reviewer truth. Declare source owners and dependencies explicitly; omitted unrelated scope is not whole-project coverage. Changed sources invalidate old proof, and replacement chains cannot hide earlier obligations. A JSON corruption or identity mismatch fails without overwriting the journal. Host captures exist because `observe.mjs` serves only declared static files; do not route a server-rendered app through the observer, and do not relax `report` checks to admit host screenshots. A self-reviewed closure stays labeled `self-review` in `visual_closures`; recorded unavailable evidence stays BLOCKED (exit 2), never PASS.

- `asset_quality.py` approves only a strict self-contained structural/declared-provenance contract under explicit byte/depth/node and arc-magnitude budgets. It requires structured source/license evidence bound to metadata-relative safe regular files (or an explicitly `unverified` external source), and rejects redirected input chains, placeholder/extra/contradictory metadata, exact-byte digest mismatch, grid/live-area/viewBox mismatch, active/embedded/external/style/namespace/link content, unsupported transforms/paint, malformed/non-finite/extreme/clipped/empty geometry, embedded text/raster, and artwork that deterministically collapses at its smallest declared target. Duotone fails on undeclared tones, unknown or changing layers, a secondary without a primary, or any muted opacity outside the secondary layer; muted opacity stays rejected in every other mode. Same-winding nonzero holes and sub-pixel fill details only warn. Exact curve extrema stop false clipping from control points, but a curve that truly overshoots the grid still fails: verbatim Bootstrap `heart-fill` overshoots y=0 by about 5e-5 units and is rejected under the unchanged 1e-7 interface tolerance. `--rehash` never rebinds external or brand artwork digests. It still cannot validate current external source/license truth, recognition, metaphor, silhouette, optical balance, or family/UI fit.
- `icon_review.py` binds exact candidates, metadata, structured source/license evidence, sizes, canonical comparison→host state maps (same-name states except `high-contrast` → `forced-colors`), context source digests/routes/selectors/labels/viewports, verdict, selection, and all non-selected alternatives into a deterministic LF-normalized representative sheet. Repository-derived host proof requires a selected candidate; unresolved `REJECT | UNKNOWN` contexts must remain representative. It rejects malformed/extreme numeric input, uninspectable or redirected paths, state-label swaps, and output/input aliases. Same-kind candidates need explicit schema-1.2 `comparison_axis: style` and a declared drawing-style difference; per-state assets render only in their state cells. A `selected` host state is proven by the declared ARIA attribute, and the existing exact-label check still applies, so a host that renames itself when selected (as the literary save toggle does) cannot pass. It does not choose the winner and is not a pixel-identical host renderer. Inspect the winner and closest rejected alternative in the real owning component; custom, existing, modified surrounding UI, and no icon remain valid outcomes.
- `glyph.py` emits arcs from 3-decimal endpoints, and the validator re-derives their centers, so it demands 0.002 units of live-area clearance for curved shapes. Under even-odd, overlapping cut-outs refill (build a plus as one shape), and a detail reaching its body's edge cannot be a cut-out (limit it with `variants`). Square caps are bounded by their diagonal reach, so they need more padding than round or butt caps. Purely linear glyphs gain no mass in solid. Crisp snapping applies only to whole-pixel strokes at the base grid. Its lints are prompts, not optical approval.
- `glyph.py` character tokens change file shape, not just geometry: angled terminals, `contrast` and `miter` joins (miter is refused otherwise) turn the outline variant and the duotone primary into filled outlines (`fill` mode, no stroke attributes), so consumers that restyle stroke width or that classify outline as stroked paint (as `iso.py` does) see fills; expanded closed strokes are one nonzero path with a reversed inner edge so tight inner corners stay painted. Junction or aperture gaps under 1 CSS px at smaller targets add `<variant>-small/` files whose metadata lists only the small sizes. `proportion` and `fill` reshape keylines and `fit` shapes only; explicit coordinates are never transformed. Character families are bounded by measuring the serialized path as the validator does (`asset_quality._path_geometry`), so an expanded curve touching the live edge can be refused even though the same stroked circle passes. Byte identity for specs without character tokens is pinned by digest in `tests/test_glyph.py`; change it only deliberately.
- `brand-mark` is an explicit imported-artwork profile, not a bypass for custom icons. Supplied opaque color and the relative rounding envelope avoid false source rewrites; exact curve extrema now apply to every profile. Source/license/usage truth remains a primary-source judgment. Unsupported gradients/masks/styles need an official variant or host asset proof. Rebinding a delivered digest alone cannot replace retained upstream bytes. A brand's kit and current prose can disagree; preserve the evidence and select a supported variant instead of silently recoloring.
- Mixed-control alignment concerns actual input/button boxes, not caption/help wrappers. Geometry schema 1.1 needs an explicit axis, one reference and justified finite tolerance; missing/ambiguous/pseudo geometry cannot be waived. Wrapped rows and approved staggered targets are legitimate counterexamples. Numeric equality does not prove text baseline or optical finish.
- `contrast.py` accepts exact opaque colors. It does not composite alpha, gradients, images, blend modes, overlays, or state opacity.
- `iso.py` output is compared byte for byte with committed examples on Ubuntu, Windows and macOS. Platform `libm` sin/cos can differ in the last bit, so `_fmt` rounds to six places before the final two; a value on a rounding boundary (379.685) otherwise printed 379.68 on macOS and 379.69 elsewhere. Keep that two-stage rounding when changing number output.
- `iso.py` treats each solid as its bounding box, so a chip's pins (0.18 grid units), a screen stand, or a building's plinth, canopy or roof sign can collide with a neighbor whose drawn faces would not touch; it refuses a cycle or a two-sided connector instead of splitting geometry. Connectors stay on one level: objects standing at different heights need an explicit shared `z`, a route to the platform they share, or (schema 1.1) `route: "ground"` with risers, which still cannot reach an object standing on a platform because its riser would pass through the platform. Schema 1.0 output is frozen: every 1.1 behavior, including surface end points and hidden-marker rerouting, stays behind a 1.1 field, value, type or declared schema, so the 1.0 demos keep their known hidden arrowheads. Hidden-marker checks use bounding volumes with the drawn corner radius, so an irregular shape (tree canopy, core plates) can still hide a marker the check accepts. Icons resolve beside the scene file (`render_file`) or against the `base` passed to `render()`. Label fit is a character-width estimate, so a warning-free render still needs inspection with the real font. Committed `docs/iso-examples/*.svg` and manifests are compared byte for byte by the tests: re-render the examples after any change that alters output. Schema 1.2 is opt-in for the same reason: its new defaults (tree species and size, stands on screens, lobbies, parapets, rooftop plant, 1 px detail strokes) apply only to scenes that declare 1.2 or use a 1.2 field, so the frozen v2 keeps its known shadow overhang and sub-pixel hairlines. 1.2 placement is seeded: changing `seed`, a size or `detail` reshuffles rooftop plant, board parts and tree variation. A 1.2 shadow is clipped only to a support whose body top equals the object's base and holds its footprint center, and an object with no support casts none. The label-collision check is cross-object, uses estimated text widths and convex hulls of filled faces, and treats only objects painted after a label as covering it. Upright labels suit square faces; on long or tilted faces they warn. Schema 1.3 is opt-in the same way, and it changes more than paint: core packages keep a wider margin, signs default to the 9 px `canopy` or `plaque` mount (below the 11 px label rule, because signage is part of the drawing) and slabs carrying a building are paved. Its dark ramp lives in `light-dark()` fallbacks behind `@supports`, so a page must set `color-scheme: dark` (or define `--iso-*` itself) to get it, and several inline SVGs share one document's stylesheet rules. Board routing is seeded per bundle and a higher `detail` routes the same bundles first, so detail never lowers the trace count, but changing a seed, a core size or the label reshuffles every route; a board too small for its package gets short stubs or none. The platform-overlap warning compares convex hulls of filled faces with the platform's top face in screen space, so a tall object near a platform's front corner usually warns even when the volumes are far apart; the silhouette warning compares the same hulls between any two objects that neither stand on each other nor share a platform, so upright cards in a row need about 0.5 grid units between them and a monitor must clear a rack's side, not only its top. Move one, stack it or set `attach`. A hedge's volume stays whole where a walk opens it, so nothing may stand in the opening, and a canopy sign that will not fit its fascia at 7 px warns rather than widening the portal.

## Benchmark and browser evidence

- All five businesses are fictional. Their artifacts are rendered/browser regressions, not observed-agent or causal model evidence. Goodturn generated imagery is not engineering truth; keep its disclosure, local font licenses, original-asset metadata, and pinned Lucide source/license metadata distinct.
- Forward-test screenshot filenames are a manifest/test contract. Rerun `node scripts/browser-smoke.mjs --capture` after material visual changes.
- `observe.mjs tells` infers `app` or `marketing` at the widest width, because narrow layouts hide sidebars: a tall navigation column means app, an `h1` of 40 px or more means marketing, otherwise six or more fields and tables mean app. Control-size checks skip tabs, options, menu items, table cells, unboxed link-style buttons and multi-line buttons (cards and list rows built as buttons), and optical-size names such as Sitka Text and Sitka Display count as one family; the copy budget applies only to marketing pages. It emulates desktop layout at every width so the width is exact, and reports a missing viewport meta separately. Left edges on plain blocks are `left-rule` checks, not tells, so timeline axes and quotes do not fail; a signature left rule needs `--allow left-stripe` with a recorded reason. A slow browser exit becomes `cleanupWarnings` instead of discarding completed findings.
- A cold browser can take more than 15 s to expose DevTools on a hosted Windows runner (a CI job failed that way), so `observe.mjs` waits up to 45 s (`BROWSER_START_MS`) before reporting that it did not start; a browser that exits early still fails at once. `scripts/browser-smoke.mjs` also waits 45 s and kills a Chrome that never exposed a page; before that fix the orphaned browser kept the smoke job alive until CI cancelled it.
- Browser smoke uses system Chrome CDP and catches runtime/interaction failures, not taste. Manual in-app review remains necessary for composition and optical hierarchy.
- Measure final component geometry only after the scoped owning transition has stopped and its bounds are stable; ancestor transforms make otherwise correct descendants appear fractionally smaller during entry motion.
- Keep selector scopes specific: the warehouse first pass showed how shared `[data-filter]` attributes on controls and rows can corrupt state.
- Model durable object state explicitly: setting `hidden` before a recomputation can be undone, as the initial resolution flow demonstrated.
- Check inherited responsive grid placement at every breakpoint; the literary tablet membership placement initially leaked into phone order without causing overflow.
- Full-page and viewport screenshots serve different evidence. Fixed elements can appear misleadingly in full-page state captures.
- A headless window-size flag or screenshot pixel width alone can describe a crop of a wider layout. The visual-acceptance capture route explicitly emulates and reads back CSS viewport geometry before capture; distinguish capture defects from product overflow before changing CSS.
- No horizontal overflow does not prove readable display type: emergency wrapping can split ordinary words while containment checks pass. Likewise, supplied brand adjectives do not prove that a newly invented composition was already accepted. The additional local probes summarized in `evals/visual-acceptance/README.md` expose these boundaries without claiming a completed independent generation study.

## Installer boundary

- Keep YAML frontmatter scalars valid: descriptions containing colon-space must be quoted or block scalars. The installer's bounded metadata recognition is not a general YAML parser; a successful copy alone cannot establish skill-host loadability.

- The repository installer owns a short-lived destination lock and per-run transient staging/backup claims. It preserves recognizable interrupted previous state until staging succeeds and must never treat a forgeable stale marker as permission for recursive deletion.
- Validate the source, completed staging tree, and activated destination. Expand Windows short names through the longest existing ancestor without resolving reparse targets, then recheck both original and long lexical spellings before containment, locking, and swaps so aliases cannot bypass overlap checks or split ownership identity. Copy or rename success alone is not proof that a concurrent path swap stayed safe. The post-swap checks are still path-based; complete protection against a hostile same-user TOCTOU adversary would require platform-specific secure directory handles.

## Current validation gaps

The repository has unit/regression, deterministic contract, exact standalone-install, compile, cross-platform CI browser smoke, screenshots, manual rendered QA, an operational icon comparison, and a bounded observed-host scope series. The host series is small, single-configuration, noncausal, and cannot observe exact token totals or runtime self-identity; it is not a reproducible population comparison. The repository still has no lint/format, static typing, coverage, package/plugin publication verification, automated visual diff, full accessibility engine, local deployment verification, production backend tests, or icon recognition/usability study. Aesthetic and optical quality remain human/rendered judgment.

## New visual-evidence boundaries

- Schema-1/2 reviews are historical inputs, not new PASS evidence. Preserve them even when bound source/runner changes make them stale. New plans explicitly cover combinations and owner/detail crops; thumbnails cannot settle small material or glyph artifacts.
- The optional observer serves complete declared static scopes and hides native scrollbar paint. Do not replace real interaction, backend, closed-shadow/media or independent visual evidence with PNG/hash checks.
- Custom SVG structural PASS and original provenance do not establish optical finish. Targets must match actual slots; the icon manifest enforces exact context coverage. Inspect native owners, label gaps, small counters and diagnostic joins.
