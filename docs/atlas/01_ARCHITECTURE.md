# Architecture

## System overview

Snowe UI Skill is an installable `SKILL.md` design practice plus a standard-library Python decision-support runtime. It is not a web service, Python package, daemon, or hosted application.

Two product paths share one purpose but execute in different hosts:

- A compatible agent runtime discovers `skill/snowe-ui-skill/SKILL.md`, follows only references relevant to the live decision, researches or generates assets when justified, implements in the target repository, and performs rendered critique.
- A Python 3.11+ process runs `skill/snowe-ui-skill/scripts/search.py` for explicitly selected CSV evidence or an unresolved architecture-first decision packet. The Python runtime makes no network request and does not implement designer judgment by itself.

Repository-only deterministic contracts, five rendered implementations, an operational icon-decision comparison, screenshots, browser smoke, bounded observed-host probes, and the public Doppler Pages showcase provide distinct evidence surfaces without becoming part of copied skill installations. The host probes record specified tasks, configuration, loaded references, process depth, and limitations; they are a small noncausal observation set, not proof that Snowe alone caused the behavior.

## Runtime graph

```text
search.py (CLI)
├── core.py
│   └── caller-selected configured CSV or stack catalog
└── decision_packet.py
    └── core.search("product") only when caller supplies analog_query

asset_quality.py (standalone SVG/metadata validator)
icon_review.py   (standalone representative-control icon comparison builder)
glyph.py         (token-spec icon-family builder)
└── asset_quality.validate_svg_asset on every staged output
contrast.py      (standalone exact-color checker)
```

### `search.py`

Owns CLI argument constraints and dispatch. It requires an explicit evidence domain, explicit stack, or packet mode. `--design-system` is only a compatibility spelling for `--decision-packet`; `--analog-query` is packet-only and caller chosen. Windows console output is normalized to UTF-8 when required, only when run as a script; `main(argv)` is importable for in-process tests. Lookup errors exit 1 (text on stderr, the JSON error object on stdout with `--json`); lock contention exits 1 without a traceback. The persistence confirmation reports the resolved directory and each file's `written`/`preserved` status from `generate_decision_packet_with_persistence`, which returns the formatted packet plus the `persist_decision_packet` result; `generate_decision_packet` keeps returning only the formatted packet.

### `core.py`

Owns `CSV_CONFIG`, `STACK_CONFIG`, `RETIRED_STACKS`, query/row normalization and in-process weighted-field BM25 with name matching, exact searchable/output headers, evidence roles/warnings including unmatched query terms, icon-row exclusion, and exact icon-candidate family constraints. It deliberately has no automatic domain detector or layout/style/palette/type/motion recipe domains.

### `decision_packet.py`

Owns schema `3.0`, verbatim brief preservation, unresolved-first framing, pass-through caller declarations, language/ambiguity policy, optional product analog evidence, open architecture/art-direction/asset/motion/responsive/evaluation contracts, Markdown/JSON formatting, and identity-bound `design-intelligence/` persistence. Persistence requires an explicit printable project identity, rejects Windows-reserved or colliding project/page slugs, serializes one project with an OS-backed lock, preflights page identity before replaceable inquiry writes, uses atomic replace/create operations, rejects redirected or shared-file targets, and byte-preserves an existing accepted ledger. It performs no language detection, translation, keyword signal classification, query expansion, work-mode inference, platform inference, or default pressure inference.

### Validators

Symbol source choice precedes custom exploration: third-party identities retain verified supplied artwork, learned actions retain meaning, and open product-specific symbols use the native-owner drawing/repair loop. `asset_quality.py` keeps the default `interface-icon` contract and adds explicit `brand-mark` metadata schema 1.0 with external provenance, unchanged upstream-artwork and usage byte bindings, and supplied opaque colors. Both profiles bound curves by exact quadratic/cubic extrema under bounded arithmetic. Its imported-only containment envelope is 1e-7 of the smaller viewBox dimension for source decimal rounding; the default icon containment tolerance stays absolute. Unsupported official assets use an appropriate official variant or host asset proof rather than a redraw. Icon comparison schema 1.2 binds explicit identity roles and forbids custom brand substitutes; 1.0/1.1 remain supported. `visual_system.py` schema 1.1 adds declared owner-axis geometry with justified numeric tolerance and an unambiguous reference; schema 1.0 retains exact-property semantics. None certifies source truth, optics or acceptance.

`asset_quality.py` checks a deliberately strict self-contained SVG subset plus companion metadata: exact-byte provenance digest, structured local source/license evidence, external/original source shape, drawing language, grid/live-area/viewBox geometry, bounded finite path/arc geometry, painted visibility, small-target viability, unsafe/external content, `currentColor` stroke/fill/mixed/duotone contracts, and explicit byte/depth/node budgets. Its `--init-metadata` and `--rehash` modes write a placeholder skeleton and rebind original/local digests without relaxing any check. It rejects symlink/junction/reparse input chains (only the macOS root aliases `/tmp`, `/var` and `/etc` that resolve into `/private` are accepted) and returns bounded failures for malformed input. `icon_review.py` validates typed manifest decisions, existing/custom/no-icon candidates (or a drawing-style comparison with per-state assets), declared sizes/states, exact assets and metadata, structured evidence bindings, digest-bound repository context, one-to-one comparison→host state maps (`high-contrast` → `forced-colors`), host routes/selectors/labels/viewports/states, output/input non-aliasing, and deterministic regeneration before producing a self-contained representative comparison sheet. Neither command verifies external provenance/license truth, recognition, metaphor, or optical/UI quality.

`glyph.py` (spec schema `1.0`) compiles family tokens (grid, padding, stroke, caps, round/bevel joins, corner radius, detail density, dot, snap, crisp, duotone tone) and grid-snapped primitives (line, polyline, circular-arc path, arc, circle, ellipse, rect, rounded-rect, regular polygon, gear, chevron, arrow, dot) with rotate/repeat/radial/mirror transforms into centerline geometry. Each glyph renders `outline` (strokes, or mixed with dots), `solid` (bodies offset to the outline's outer edge with matching caps/joins, details as even-odd cut-outs, strokes outlined as fills) and `duotone` (a secondary fill of bodies under the outline primary). Metadata follows the validator's interface-icon schema with original provenance and source evidence bound to the copied spec. It stages every file beside the output, validates each SVG with `asset_quality.py` and publishes only when all pass; output and the optional self-contained contact sheet are byte-deterministic. Refusals cover unknown fields/primitives, strict JSON, off-grid or non-finite values, live-area overshoot (arcs keep 0.002 units of clearance for rounded endpoints), sub-0.5 px strokes, invalid solid cut-outs and family budgets; keyline, gap and sliver lints only warn and certify nothing optical. `contrast.py` measures exact opaque pairs and rejects alpha/unsupported syntax rather than guessing compositing.

### Repository installer

`scripts/install_skill.py` is repository tooling, not part of the copied product. Its copy ignores caches, `.env*`, `*.log`, `node_modules`, `.git` and local `design-intelligence/` state, so stray local files never ship. The default destination is `~/.agents/skills`; README documents `--destination ~/.claude/skills/snowe-ui-skill` for Claude Code. It acquires an OS-backed destination lock, validates lexical/physical containment and a regular self-contained source tree, claims per-run transient slots without treating forgeable stale markers as ownership, preserves a recognizable interrupted previous tree until staging succeeds, stages and revalidates an exact copy immediately before activation, revalidates the activated object, safely restores the current or recovered prior destination on failure, removes obsolete files on update, and accepts an explicit final destination for compatible hosts.

## Lifecycle and invariants

- Runtime paths resolve relative to the copied skill directory, never the repository root.
- Deterministic framing prefers `UNRESOLVED` to a plausible but unverified semantic guess; caller declarations are not restricted to built-in vocabulary.
- Architecture and art direction remain open until an agent compares real candidates; packet generation is not design completion.
- Detailed methods remain behind conditional direct links from `SKILL.md` for progressive disclosure.
- Existing code is a baseline, not evidence of an accepted visual direction. Explicit rejection reopens the affected choice at Focused depth; original design requires a positive product-specific intention and whole-screen finishing, separate from technical fixture checks.
- Density is a scoped composition decision before dimensions are propagated. The quality gate compares empty/sparse/populated repeated-use states with a tighter challenger when that choice remains open, preserving target/text size and justified stable workspace geometry. `evals/density` supplies an authored analogue and source-bound before/after evidence, not an automatic compactness score.
- Typography acceptance checks explicit role contracts from evals/typography/goodturn.json: family, weight, style, line-height, tracking, variable settings and pinned font files/face declarations. Browser evidence covers cards, controls, navigation and open dialogs, plus deliberate mutations. Placement/scroll acceptance distinguishes bounded work regions from document flow and geometric from optical alignment.
- Scoped user corrections use the installable corrections CLI and identity-bound CORRECTIONS.json with atomic updates, history, explicit scope and hashed source/artifact proof. Existing DECISIONS.md remains byte-preserved. Applicable open or stale obligations block completion; this is evidence integrity, not machine visual judgment.
- New or original design work (Focused or Portfolio, a new identity) defaults to a custom `glyph.py` family that keeps learned metaphors for familiar actions and invents only for product-specific concepts; a library is the fallback for breadth or an accepted system that already uses one, Direct work in an accepted system keeps its family, and brand marks stay official artwork. Custom candidates still need native-size semantic, optical, host/backing and accessibility acceptance. The icon comparison helper gives text-bearing states full-width rows; browser proof checks cell-level content containment and detects the original narrow-row failure via an injected regression probe.
- New/material visual systems pass a scoped early rendered comparison before propagation. Visual acceptance has explicit blocking findings, same-content subtraction when treatment value is unresolved, preservation of justified shape/brand roles, and `UNKNOWN` for missing required proof; Python packets repeat the evidence boundary without judging aesthetics.
- The quality gate explicitly exercises changes that invalidate an already-visible derived preview/result: current output must refresh or invalidate, with input retention, recovery and dependent state cues proved. Historical/accepted records remain distinct. This is affected-state proof rather than automatic whole-journey expansion.
- A definite supplied design closes its specified visual decisions: conformance compares target and implementation, including control geometry, without unauthorized restyling. A brand/content brief alone does not close composition; unresolved affected visual choices still need Focused comparison. Fidelity, source-design critique, and functional/accessibility acceptance are distinct claims.
- Local catalogs require explicit activation, expose evidence roles/limitations, and can be absent without changing the reasoning contract. Stack results additionally report returned-row `Docs URL` coverage without treating URL presence as authority or freshness proof.
- Process breadth follows observed consequence, actual owner/consumer change surface, material uncertainty, and reversibility. A high-consequence bounded correction raises proof intensity without automatically widening to architecture.
- Creative search breadth is independent of architectural scope: an open visual thesis may compare multiple directions at Focused depth while owners and settled product contracts stay fixed. Direct repairs, exact supplied targets and accepted quiet utility gain no novelty obligation. Art direction translates verified sources into perceptual mechanisms and rendered proof; material successful inventions remain conditional project hypotheses.
- `evals/creative-search/run_pilot.py` is opt-in repository-only real Codex CLI generation/capture tooling with complete frozen skill copies, frozen held-out briefs, neutral temporary subject workspaces, exact prompt/artifact checks and exposed timing/usage. Snapshots can freeze this product, any `--source` skill copy, or a `--no-skill` control, with a selected `--briefs` file and optional seeded starting code; a no-skill run refuses to start while a global Snowe installation is discoverable. It does not run in normal CI or certify taste; raw host evidence stays in ignored `work/` and durable summaries remain in the evaluation directory.
- Persistence serializes each project, preflights identities before replaceable writes, atomically regenerates `BRIEF.md`, identity-binds project/page slugs, handles recoverable torn manifests, revalidates page parents before publication, and byte-preserves an existing `DECISIONS.md`.
- Python product/runtime remains standard-library and 3.11+; The copied product also offers an optional Node 22/system Chromium observer; repository browser scenarios stay outside the copied product.
- Benchmarks are fictional rendered regressions, not causal model proof, installable product behavior, or production integrations; the Doppler Pages site remains a static public demonstration with no purchase/payment backend.

There is no database, long-running product process, shared runtime cache, telemetry path, network client, package manager, or browser dependency in the installable Python runtime. Project persistence and the repository-only installer use short-lived OS file locks plus filesystem identity/atomicity; neither creates an ongoing service.

- Six authored acceptance tasks under evals/acceptance-cases exercise retained typography, role drift, contextual custom icons, backings, multilingual bounded lists/alignment, and correction continuation. Hash-bound PNGs and implementer self-review remain separate from technical assertions and generalization claims.
- The primary skill entry is reduced to a trigger-only frontmatter description ("Use when…", no workflow summary), a short glossary (owner, consumer, invariant, change surface), one source-precedence list (accepted scoped decisions rank above current rendered behavior until their revisit trigger fires; cli-reference links to it instead of keeping its own), a Records section that separates the decision ledger (`DECISIONS.md`) from the correction journal (`CORRECTIONS.json`) and says which records stay in working notes, which become files and when, and what goes in the reply, scoped depth rules (a known fix in a shared owner stays Direct when it cannot change other consumers' rendering; a new single page with a known job is Focused, a new multi-page product Portfolio), a grouped routing list that links every reference, a short execution/proof loop whose render step gives Direct work its own checklist and sends Focused and Portfolio work to anchored quality-gates sections, and concise delivery in the user's language. `references/exploration-protocol.md` does not restate the depth rules: one table says which of its sections each depth uses, what it records and when it stops. Document fingerprints identify revisions; short concept anchors, forbidden global obligations, a routed-reference check (every `references/*.md` linked from SKILL.md) and authored route scenarios provide bounded contract checks without freezing section wording.
- The repository installer diagnoses duplicate copies and explicitly migrates the legacy location into a digest-recorded backup outside discovery; retry and post-move failure recovery preserve old files.

## Known-page composition boundary

`references/page-hierarchy.md` owns the Focused page map, useful-copy audit and action identity (`operation + target + outcome + context`) before component choice. The root router, exploration and architecture references route known page jobs here; unresolved page jobs or wider product contracts retain Portfolio framing. Direct property corrections do not create a page-map document. These clauses and the existing six scope traces are explicit authored contracts, not an automatic task classifier. Technical, evidence-integrity, visual and user-acceptance outcomes stay separate.

`references/surfaces-and-disclosure.md` owns where each group or secondary task lives (main surface, side panel, dialog, popover, tabs, in-place disclosure or route), the balance between overloaded and over-hidden screens, context retention and the narrow-width transformation; the page map records the chosen `surface`. `references/design-foundations.md#stable-geometry-across-states` owns the frame-stability contract (frames and controls keep their size across loading, selection, validation, saving and live updates), and quality gates compare frame geometry across those transitions. SKILL.md requires every visible string to be data, state, an action label or useful guidance, and fixes the user-facing reply order (what changed, how to verify, what remains open).

`references/app-patterns.md` owns behavioral defaults for repeated-use applications: navigation shells, list/detail, search, filters, sort and long collections, bulk actions, loading/empty/error/stale states, undo versus confirm, optimistic updates, saving, toasts, create/onboarding/settings/destructive flows, keyboard use and mobile specifics. It does not choose visual style.

`references/data-visualization.md` owns chart and dashboard guidance: chart form chosen by the viewer's question and when a table wins, encoding accuracy (zero-baseline bars; 3D, crowded pies and dual axes as default/deviate-when exceptions), direct labels versus legends, categorical/sequential/diverging/highlight series color and dark mode, number, unit and period formatting, KPI tiles and sparklines, dashboard scope (one shared range, per-panel disclosure of filters that do not apply), chart states, touch and keyboard readouts, and text/data-table alternatives. `references/localization-and-rtl.md` owns `lang`/`dir`, bidi isolation, logical CSS properties, RTL mirroring rules, text expansion and truncation, script line height and font coverage, and `Intl` formatting. `references/html-email.md` owns HTML email constraints (table layout, ~600 px, inline CSS, classic Outlook's Word engine, Gmail's 102 KB clipping, dark-mode inversion), bulletproof buttons, font fallbacks, alt text, preheader, plain-text part and real-client testing. The `Review-Only and Audits` section of `references/quality-gates.md` owns the output contract when the user asks for a review or audit without changes: no repository edits, a stated scope, one finding record (severity, location, evidence, why it matters, fix, `verified | suspected` status) ordered by severity, suspected findings kept separate as `UNKNOWN`, and accessibility findings cited against the existing WCAG threshold table. SKILL.md routes to it with its own link. The rest of `quality-gates.md` runs purpose, a single Verdicts section (verdict meanings, method versus verdict, finding record, disposition table, missing-proof rules), the rendered review loop, the critique checklist, accessibility, responsive and state checks, special checks (conformance, early gate, detail and artifacts, icon backings, typography coherence, density/placement/scroll, repository and performance) and delivery evidence; checks owned by other references are listed by link.

`references/failure-patterns.md` owns the generic-output diagnostics (symptom, usual cause, check, constructive replacement, legitimate exception) used before accepting an original visual design; it is an inspection list with explicit exceptions, not a style ban or a substitute for a positive direction. Its Recorded Incidents section holds single-incident worked examples (the rotated-can lid built from projected boxes, a focus ring inheriting text `currentColor`, a stretched tablet menu, section numbering added as polish, a field caption that pushed its input off the row axis, accents that kept collapsing to pale tints, pills replaced with square buttons, a variable font reported as ExtraLight, a screenshot narrower than its layout, report notes inside the product screen); general references keep one-sentence principles that link there.

`references/design-foundations.md#starting-points` owns explicit default craft values (typography, spacing, color, dark theme, elevation, states and focus, forms, data tables) framed as starting points to beat with a recorded reason; an accepted system's values take precedence, and local catalogs still never choose style, palette or typography.

`references/art-direction-gate.md` owns art-direction construction: sourcing a direction from the subject's materials, artifacts, vernacular and working conditions instead of adjectives; one signature move (the identity carrier) with a one-or-two-loud-axis contrast budget; color proportions with one job per accent; composition moves; translation into role-named tokens; two or three directions that differ in signature move and a loud axis, with a type-and-space reduction as the control; and three short worked derivations. It is the single home of the font-pairing method (display/text/mono roles, two families plus a mono as a starting ceiling rather than an acceptance rule, x-height and script coverage checks, fallback stacks, the local `google-fonts` index as a filter that never chooses); `design-foundations.md#typography` keeps the role contract and role map, and `quality-gates.md#typography-coherence` owns rendered-font verification and states that family count is not an acceptance criterion. Depth, verdicts, selection and when to ask the user stay in SKILL.md and `exploration-protocol.md`; Direct work does not load it.

Visible ordinals are part of that copy/relationship audit. The failure-patterns numbering incident owns the rule against automatic `01/02` landing-section/benefit/service prefixes and the exceptions it preserves (actual process order, useful navigation/references, factual data and explicitly supplied identity); page-hierarchy and quality-gates link to it. Open numbering treatments use same-content comparison; no keyword classifier, numeric quota or runtime taste verdict selects the outcome.

## Explicit visual review contract

`visual_review.py` checks new schema-3 reports against schema-2 attention contracts, independently bound observation plans and scoped visual-system revisions. `references/cli-reference.md` documents these tools (Observe in a Browser, Version a Visual-System Contract, Check a Recorded Visual Verdict); the former `visual-system-and-observation.md` was folded into it, and its paint-tracing judgment lives in the quality-gates detail check. `observation.py` owns complete declared combination/source inventories, actual browser metadata, whole/detail PNG and temporal bindings. `visual_system.py` owns component/role/token/owner/consumer/layer maps, observable relationships, exceptions and conditional hypotheses. Method, recorded verdict, integrity and user acceptance remain distinct; none grades taste. Historical schema-1/2 reports remain readable but cannot mint PASS. New visual correction verification requires method, explicit KEEP and either a current linked report or a bound host capture; old inline receipts need renewed verification without history rewriting.

The repository-only `evals/visual-judgment` cases contrast technically valid A/B weaknesses with a corrected C and restrained D across running/completed/error states. `scripts/visual-judgment.mjs` handles their browser proof through the canonical lifecycle. Formal reports record implementer self-review; source/record validation never establishes independent quality.

Color selection guidance assigns the agent the reversible palette decision before implementation, grounded in product context and full-surface roles. The repository-only color-intensity extension to visual-judgment tests role-specific fill/foreground and canvas/table/dialog paint. Ocean/plum examples retain technical success but explicit contextual rejection; the fixture palette JSON is not an installable color catalog or universal chooser.

The iconography reference owns autonomous control label-mode selection (icon-only, text-only or combined) by action recognition, context, density and input, with scoped in-control comparison only for unresolved choices. Icon-only controls retain accessible naming and hover/focus help; ambiguous or consequential actions retain needed visible wording. Design foundations and quality gates route to that section without reopening icon sourcing for a bounded caption change. Passive service/data/form labels are outside that removal scope.

The iconography reference also owns the family style decision (outline, solid or duotone per family and role, platform conventions first, solid for selected state and very small or on-image glyphs, a rendered style comparison when open) and the library-variant inventory and the default-source policy; `icon-craft.md` owns drawing judgment and the `glyph.py` family workflow (tokens derived from text stems, control radius and type terminals; learned versus invented metaphors; label-less 16 px, squint, neighbor and state tests), while `glyph.py` derives solid and duotone forms from one construction.

## Portable observation and regenerated Doppler

`observe.mjs` is a self-contained optional Node/CDP adapter: capability discovery, isolated loopback static serving, state replay, measured layers/rendered fonts, complete scoped source/resource closure, immutable whole/detail captures, bounded temporal sequences and a paired comparison viewer. It uses only Node built-ins and a system browser. Headless native scrollbar paint is hidden for stable capture geometry; native scrollbar behavior, application-server builds, external resources, closed shadow content and independent visual judgment remain host responsibilities. Python remains standard-library-only.

The regenerated Doppler page separates `can.css` from composition, attaches its top plane to the cylinder's 3D owner, uses five original control masks and finite authored choreography. Its anchored menu and native confirmation dialog share the page's type/material hierarchy and have keyboard/text-pressure proof. `references/overlays-and-selection.md` owns conditional visual composition guidance for secondary surfaces; `references/icon-craft.md` owns actual-slot optical review. The old accepted ledger is byte-preserved. `REGENERATION.md` and `evals/doppler-regeneration/` separate new selection, old/new integrity controls, real-browser detail injections, current self-review and unconfirmed user acceptance. `scripts/doppler-detail-probe.mjs` copies product and target into an isolated workspace and injects construction, paint, mask, icon-host and visibility defects; no Doppler semantics enter installed tools.
