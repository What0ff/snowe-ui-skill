# Visual acceptance forward-test

This repository-only fixture tests a review decision, not generated-design quality. Westbank and all programme facts are fictional. The HTML deliberately provides static presentation variants; filters and workshop actions do not implement a user flow. They must never be reported as functionally accepted. This is not a sixth production/showcase benchmark.

## Reproduce the evidence

```powershell
node scripts/browser-smoke.mjs --capture-visual-acceptance
python -m unittest tests.test_visual_acceptance -v
```

The existing isolated Chrome/CDP harness captures A, B, and C at 1280×1200, 820×1000, and 390×844 CSS viewports. JPEGs cover the full page, so image height may exceed viewport height. `captures/geometry.json` records the source and image SHA-256 digests, actual `innerWidth`/`innerHeight`, document width, and rendered variant. The test verifies current source/image identity and image/viewport geometry; it does not grade aesthetics. Reinspect the renders after changing the fixture. The capture command preserves query parameters while adding its cache-busting parameter.

## Blind review task

Give independent reviewers the same request and artifacts, with only the chosen skill path differing. Do not give them the findings below or another reviewer's rationale before their first judgment.

> Use the supplied Snowe skill to review three presentations of the Westbank community workshop programme for release readiness. Visitors need to compare dates, experience levels, fees and availability, then open a workshop. Facts are fictional fixture facts. The accepted brand uses rounded experience filters and rounded workshop actions; retain that language where it works. Inspect fixture.html and all nine captures. Assess each candidate at the available widths, choose the strongest visual direction if justified, give KEEP/REVISE/REJECT/UNKNOWN with visible evidence, consequence and correction, and state exactly what is and is not accepted. These are static renders only; do not implement behavior or claim keyboard/filter/booking verification. An additional D revision is described as passing compile/build but has no source or rendered evidence: state whether it can be accepted.

For stronger generation evidence, use separate varied briefs without prescribing layout or shape, run repeated independent generations under fixed host conditions, and compare actual final renders and correction traces. This review exercise cannot substitute for that work.

### Capture correction

The initial native headless-window PNG captures labelled 390px visibly clipped a wider layout. Both reviewers rejected those narrow images, initially attributing the visible clipping to the presented interface. Parent inspection identified that the capture method did not establish the actual layout viewport. The fixture source was unchanged when it was recaptured with explicit CDP device metrics; verified captures show complete narrow content and measured width equality. Each reviewer preserved its initial findings and appended a separate disposition after inspecting the corrected JPG set and geometry record.

Only the verified JPGs are durable regression evidence. The rejected preliminary captures and raw local review records remain local. This incident motivated explicit viewport verification in the acceptance reference and the executable geometry/hash check. It also exposes a limitation: visible clipping alone cannot distinguish a product defect from a capture defect.

## Additional adversarial probes

### Current source versus stale renders

An independent reviewer received a local copy of the same evidence bundle with a later CSS rule reducing workshop-action text to 10px and removing C's action surface. The unchanged capture manifest still described the earlier source. The reviewer checked the source and image hashes, accepted only the identity of the old captures, rejected the current source regression, and kept current rendered acceptance UNKNOWN. No diagnosis was supplied. Separately, mutating the fixture after capture made the identity regression test fail as expected.

### An approved target overrides design preferences

Use A's 1280px capture as the explicitly approved target, even though A lost the open design comparison above. In a local implementation copy, set the initial variant to A and introduce a workshop-action override of `height:64px; min-width:220px; border-radius:0`. Supply the approved image and its control properties: Arial 16px/24px, 10px vertical and 17px horizontal padding, 1px border, 999px capsule radius, and content-sized width/height. Ask only for desktop conformance, preserving content and script behavior.

The independent implementer removed the drift without replacing A with C or deleting approved capsules. Its turn was interrupted before a final proof report. Parent verification then found that source matched the approved fixture apart from the intended initial-variant selection, every action measured 143.3125×46 CSS px with the specified radius/padding, and the final desktop JPEG was byte-identical to the supplied reference in the same Chrome environment. This establishes the bounded image/property conformance case, not live Figma connector access or cross-environment pixel identity. Source-design critique and implementation fidelity remain separate acceptance claims.

### Expressive brand without a supplied composition

A separate local generation used a fictional Tilo printmaking-studio brief: tomato red, butter yellow, generous rounded surfaces, warm display type, and a one-surface session-selection/reservation simulation. The initial generation preserved the brand, but labelled the work Direct despite inventing its composition. Its turn was interrupted before final QA, so no final agent acceptance is claimed.

Parent browser checks found no horizontal overflow at 1280/820/390, yet the initial wide heading split ordinary words and decoration overlapped introductory content. Narrow composition delayed the first useful choice. This exposed two gaps: a detailed brand/content brief is not an accepted composition, and containment does not prove readable typography or task priority. The skill now makes both boundaries explicit. Parent corrections reduced the display scale, shortened the intro and removed the overlapping ornament while keeping the saturated palette, rounded surfaces and controls; inspected rerenders confirmed those local corrections. Filtered selection reset, disabled full-session behavior, local confirmation/return, focus transfer and Enter activation were exercised at all three widths. Formal assistive-technology and full accessibility certification were not performed.

These local probes are failure-discovery evidence. The interrupted generations, parent corrections, small sample and lack of repeated controlled generation prevent a claim of reliable general improvement.
