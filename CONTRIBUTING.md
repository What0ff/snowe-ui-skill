# Contributing to Snowe UI Skill

Thank you for helping improve Snowe UI Skill. Contributions should make the
skill more reliable, evidence-driven, accessible, or easier to validate.

## Development setup

1. Fork and clone the repository.
2. Create a focused branch for one change.
3. Use Python 3.11 or newer.
4. Run the test suite before opening a pull request.

No third-party Python packages are required for the runtime or tests.

```bash
python -m unittest discover -s tests -v
python -m compileall -q skill/snowe-ui-skill/scripts
python evals/designer-behavior/run_eval.py
python scripts/install_skill.py --help
python scripts/check_contributor_context.py
python scripts/atlas/generate_atlas.py --check
```

Rendered benchmark changes also require Node 22 plus a local Chrome/Chromium smoke pass:

```bash
node scripts/browser-smoke.mjs --smoke
```

See [`docs/atlas/07_TEST_MATRIX.md`](docs/atlas/07_TEST_MATRIX.md) for
change-to-test routing, focused checks, environment requirements, and known
validation gaps.

## Repository context

[`AGENTS.md`](AGENTS.md) is the repository-wide guide for human and AI-assisted
work. It defines the product boundary, architectural invariants, progressive
context-loading workflow, completion rules, and atlas synchronization contract.
Start with [`docs/atlas/00_README.md`](docs/atlas/00_README.md), then use its
router instead of loading every architecture document.

The atlas and its generator are public repository infrastructure. The optional
`.agents/skills/atlas-maintainer/` workflow automates scoped maintenance for
compatible agents, but the documented Python commands work without an agent
host. None of these files is copied with the installable skill.

Maintainer-local continuity files are deliberately absent from a fresh clone.
In particular, `.codex/CURRENT_TASK.md`, `work/`, `outputs/`, `logs/`,
`PROJECT-MEMORY.md`, `HANDOFF.md`, and personal AI configuration are ignored.
Contributions and public guidance must not depend on them.

## Where changes belong

- `skill/snowe-ui-skill/SKILL.md` — core workflow and activation metadata.
- `skill/snowe-ui-skill/references/` — detailed guidance loaded only when the
  task requires it.
- `skill/snowe-ui-skill/scripts/` — deterministic retrieval, open decision
  support, and low-level validators.
- `skill/snowe-ui-skill/data/` — remaining optional retrieval evidence catalogs.
- `evals/` — deterministic packet/repository contracts; `benchmarks/` — rendered and browser-regression forward-tests.
- `tests/` — product, safety, packaging, and benchmark regression coverage.
- `scripts/install_skill.py` — exact standalone-skill installation and update helper.
- `docs/atlas/` — durable public repository architecture and navigation.
- `scripts/atlas/` — deterministic atlas maintenance tooling.
- `.agents/skills/atlas-maintainer/` — repository-only agent workflow, never
  installable Snowe product content.

Keep repository-facing documentation outside the installable skill directory.
The exception is `LICENSE`, which remains inside the skill so copied installs
retain their license terms.

## Contribution requirements

- Base design claims on source code, rendered evidence, measured values, or a
  clearly identified primary standard.
- Do not present taste, trends, or generated suggestions as universal rules.
- Preserve progressive disclosure: keep the core skill concise and route
  detailed material to a directly linked reference.
- Add or update tests for behavior changes.
- Validate CSV schema and quoting when changing data.
- Include a source URL and review date when adding guidance that depends on a
  platform, package, standard, or external catalog.
- Keep runtime code compatible with the Python standard library unless a
  dependency is justified in advance.
- Do not commit generated bytecode, credentials, local output, editor state, or
  machine-specific agent configuration.

## Keeping repository context current

After a meaningful code or configuration change, inspect the complete diff and
update only atlas claims invalidated by that change. Run
`python scripts/atlas/generate_atlas.py --write` after structural changes; the
generator owns only `docs/atlas/repo-map.md`. Before submitting any non-trivial
change, run both the contributor-context boundary check and atlas freshness
check shown above.

## Pull requests

Keep pull requests narrow and explain:

- the problem being solved;
- why the proposed behavior is stronger;
- which files and workflows change;
- the checks that were executed;
- any remaining uncertainty or trade-off.

UI guidance changes should include evidence appropriate to the claim. Large
contract changes should include regression tests or a deterministic evaluation
fixture. Claims about real-agent improvement additionally require reproducible
host/model provenance, observed reference loading, repeated runs, and a control;
rendered examples alone are not causal evidence.
